How Have I Been Pwned Protects Email Search Privacy

Scan My ShadowSeptember 10, 20264 min read

TL;DR: HIBP documents two approaches for email-breach searches: a direct API lookup, which sends the email address to HIBP, and a k-anonymity hash-range method that sends only a partial hash prefix. The latter is designed to avoid disclosing the full email address to HIBP.

There are two different search models

HIBP's current API documentation describes direct email-account searches and a k-anonymity email-search method. They solve the same problem - finding breach matches - with different privacy properties.

The direct API call sends the full email address as part of the request. The k-anonymity approach hashes the email locally and sends only a prefix of that hash.

How k-anonymity works

The client turns the email into a SHA-1 hash, sends only the first six characters to the HIBP k-anonymity endpoint, receives a set of matching suffixes and then checks locally whether the complete hash is present.

Because only a partial hash prefix is sent, HIBP does not receive the original email address through that request. The client does the final matching step.

Why the distinction matters

If you are integrating breach intelligence into an application, the way the lookup is performed is part of the privacy design.

A service that sends full identifiers to an external API should explain that clearly. A service using k-anonymity should also explain its limits rather than presenting the word anonymous as a blanket guarantee.

Do not confuse this with password checking

HIBP also uses k-anonymity for Pwned Passwords, but the password range search uses the first five characters of the SHA-1 hash rather than the six-character prefix described for email-address searches.

The important principle is the same: the complete secret or identifier is not sent in the k-anonymity request.

What users should ask any breach checker

Before entering an email, ask whether the service needs the full address, whether it stores searches, what it returns, and whether the result is used for another purpose.

HIBP publishes detailed privacy documentation, which makes its approach easier to evaluate than an unknown breach-checking site with no clear data policy.

Frequently Asked Questions

What is HIBP k-anonymity?

It is a search method where the client sends only a partial hash prefix rather than the complete email address.

Does direct API search use the full email?

Yes. HIBP documents direct email-account API searches that send the full address to the API.

How many hash characters are used for email k-anonymity?

HIBP's current API documentation describes sending the first six characters of the SHA-1 hash for email-address k-anonymity searches.

Is k-anonymity the same as zero logging?

No. It protects the identifier sent to the search endpoint; it should not be interpreted as a blanket statement that the entire web request has no operational logs.

Does HIBP use k-anonymity for passwords too?

Yes. Pwned Passwords uses a separate five-character SHA-1 hash-prefix design.
